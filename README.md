# თაობა ქვიზი — AI-ზე დაფუძნებული საგანმანათლებლო ქვიზების პლატფორმა

> სკოლა „თაობა“ — მეტი, ვიდრე სკოლა. ეს რეპოზიტორია თავდაპირველად სკოლის საინფორმაციო გვერდს შეიცავდა
> (საგამოცდო დავალება). ის შენარჩუნებულია: `public/school.html` (საიტზე: `/school.html`).

ქართულენოვანი პლატფორმა მასწავლებლებისთვის (Kahoot-ის მსგავსი):

- **AI კითხვები** Google Gemini-ით — საგნის, კლასის, თემის, სასწავლო მიზნის, საკვლევი კითხვისა და თქვენი მასალის მიხედვით (PDF, DOCX, TXT ან ჩასმული ტექსტი).
- **გადახედვა და რედაქტირება** გამოქვეყნებამდე; ხელით შექმნის რეჟიმი, როცა AI მიუწვდომელია.
- **ცოცხალი თამაში** 6-ნიშნა კოდით; მოსწავლეებს ანგარიში არ სჭირდებათ.
- **სერვერული ტაიმერი და ქულები** — კითხვა აქტიურია მთელი დროის განმავლობაში, დაგვიანებული და განმეორებითი პასუხი არ მიიღება.
- **ანალიტიკა** — გავრცელებული შეცდომები, სუსტი თემები და მიზნები, რეკომენდაციები, CSV ექსპორტი.

**ღირებულება: $0** — მხოლოდ უფასო გეგმები და ღია კოდის ბიბლიოთეკები (დეტალები ქვემოთ, „უფასო ლიმიტები“).

## 2. Supabase-ის მომზადება

1. შედით [supabase.com](https://supabase.com) → **New project**. აირჩიეთ **Free** გეგმა, ჩაწერეთ ბაზის პაროლი (შეინახეთ უსაფრთხოდ) და რეგიონი (მაგ. Frankfurt — საქართველოსთან ახლოს).
2. **მოსწავლეების ანონიმური შესვლის ჩართვა** (აუცილებელია!):
   *Authentication → Sign In / Providers* (ან *Authentication → Settings*) → ჩართეთ **Allow anonymous sign-ins** → Save.
   მოსწავლეები ამით ანგარიშის გარეშე იღებენ დროებით, უსაფრთხო იდენტობას, რომელსაც ბაზის წესები (RLS) ამოწმებს.
3. **ელფოსტის დადასტურება:** Supabase-ის ჩაშენებულ ელფოსტის სერვისს საათში ძალიან ცოტა წერილის გაგზავნა შეუძლია.
   ტესტირებისთვის შეგიძლიათ დროებით გამორთოთ *Authentication → Sign In / Providers → Email → Confirm email*.
   რეალური გამოყენებისთვის ჩართეთ ისევ და/ან დააკავშირეთ საკუთარი SMTP (*Authentication → Emails → SMTP Settings*).
4. **API გასაღებები:** *Project Settings → API* (ან *API Keys*). დაგჭირდებათ:
   - **Project URL** — მაგ. `https://abcd1234.supabase.co`
   - **anon public** (ან ახალი ტიპის **publishable**) გასაღები — ეს საჯაროა და ბრაუზერში გამოიყენება.
   - ❌ **service_role / secret** გასაღები **არასდროს** ჩაწეროთ ფრონტენდში, `.env.local`-ში ან GitHub-ზე. ამ პროექტს ის არ სჭირდება.

## 3. მიგრაციების გაშვება (მონაცემთა ბაზა)

მიგრაციები `supabase/migrations/` საქაღალდეშია და **თანმიმდევრობით** უნდა გაეშვას:

```
20261021000001_schema.sql              — ცხრილები, კავშირები, ინდექსები
20261021000002_security.sql            — Row Level Security წესები
20261021000003_game_functions.sql      — თამაშის ლოგიკა: ტაიმერი, ქულები, შესვლა კოდით
20261021000004_session_summaries.sql   — დაფის სტატისტიკა
```

### ვარიანტი ა — Supabase-ის ვებ-ინტერფეისით (უმარტივესი)

1. Supabase → **SQL Editor** → **New query**.
2. გახსენით პირველი ფაილი, დააკოპირეთ მთლიანი შიგთავსი, ჩასვით და დააჭირეთ **Run**.
3. გაიმეორეთ დანარჩენი ფაილებისთვის რიგრიგობით.
4. შემოწმება: *Database → Publications → supabase_realtime* — უნდა ჩანდეს `game_sessions`, `participants`, `answers`.
   თუ არ ჩანს, ჩართეთ ხელით ან გაუშვით:
   ```sql
   alter publication supabase_realtime add table public.game_sessions, public.participants, public.answers;
   ```

### ვარიანტი ბ — Supabase CLI-ით

```bash
npx supabase login                      # ბრაუზერში ავტორიზაცია
npx supabase link --project-ref <თქვენი-project-ref>
npx supabase db push                    # ყველა მიგრაციას ერთად გაუშვებს
```

`project-ref` არის URL-ის ნაწილი: `https://<project-ref>.supabase.co`.

## 4. Gemini API გასაღები და Edge Function

AI-ის გასაღები **მხოლოდ სერვერზე** ინახება (Supabase Edge Function-ის საიდუმლოში) და ბრაუზერამდე არასდროს აღწევს.

### 4.1 გასაღების მიღება

1. შედით [aistudio.google.com](https://aistudio.google.com) → **Get API key** → **Create API key**.
2. **ბილინგს ნუ დააკავშირებთ** — ასე პროექტი უფასო tier-ზე რჩება.

### 4.2 ფუნქციის განთავსება

```bash
npx supabase login
npx supabase link --project-ref <თქვენი-project-ref>

# საიდუმლოები (გასაღები არსად ჩაიწერება კოდში)
npx supabase secrets set GEMINI_API_KEY=<თქვენი-გასაღები>
# არასავალდებულო:
npx supabase secrets set GEMINI_MODEL=gemini-flash-latest GEMINI_FALLBACK_MODEL=gemini-flash-lite-latest
npx supabase secrets set ALLOWED_ORIGINS=https://თქვენი-საიტი.vercel.app,http://localhost:5173
npx supabase secrets set AI_LIMIT_PER_HOUR=20 AI_LIMIT_PER_DAY=60

# განთავსება
npx supabase functions deploy generate-questions --no-verify-jwt
```

- `--no-verify-jwt` უსაფრთხოა: ფუნქცია თავად ამოწმებს, რომ მომთხოვნი შესული მასწავლებელია (`supabase.auth.getUser`) და აქვს მასწავლებლის პროფილი.
- **მოდელი:** ნაგულისხმევად `gemini-flash-latest` (Flash ოჯახის უახლესი მოდელი, რომელიც უფასო tier-ზე ხელმისაწვდომია), შეცდომის ან ლიმიტის შემთხვევაში ცდის `gemini-flash-lite-latest`-ს. თუ Google სახელებს შეცვლის, უბრალოდ განაახლეთ `GEMINI_MODEL` საიდუმლო — კოდის შეცვლა საჭირო არ არის.
- თუ გასაღები არ არის დაყენებული, აპლიკაცია მუშაობს, მაგრამ AI ღილაკი აჩვენებს შეტყობინებას და შეგიძლიათ კითხვები ხელით შექმნათ.

## 5. ლოკალურად გაშვება

```bash

# .env.local-ში ჩაწერეთ VITE_SUPABASE_URL და VITE_SUPABASE_ANON_KEY (მხოლოდ საჯარო მნიშვნელობები!)
```

## 6. Vercel-ზე განთავსება

1. ატვირთეთ კოდი GitHub-ზე (თუ უკვე არ არის).
2. [vercel.com](https://vercel.com) → **Add New → Project** → აირჩიეთ ეს რეპოზიტორია.
3. Framework: **Vite** (ავტომატურად ამოიცნობს). Build: `npm run build`, Output: `dist`.
4. **Environment Variables**:
   - `VITE_SUPABASE_URL` = თქვენი Project URL
   - `VITE_SUPABASE_ANON_KEY` = anon/publishable გასაღები
   - ❌ არ დაამატოთ `GEMINI_API_KEY` ან service_role გასაღები — `VITE_` ცვლადები ბრაუზერში ჩანს.
5. **Deploy**.
6. Supabase-ში *Authentication → URL Configuration*:
   - **Site URL** = `https://თქვენი-საიტი.vercel.app`
   - **Redirect URLs** = `https://თქვენი-საიტი.vercel.app/**`
7. (რეკომენდებული) `ALLOWED_ORIGINS` საიდუმლოში ჩაწერეთ Vercel-ის მისამართი (იხ. 4.2).

`vercel.json` უკვე აწყობს SPA მარშრუტიზაციას (ნებისმიერი გვერდის განახლება მუშაობს) და უსაფრთხოების ძირითად HTTP სათაურებს.

## 7. სრული თამაშის ტესტირება რამდენიმე ფანჯარაში

1. **მასწავლებელი** (ჩვეულებრივი ფანჯარა): დარეგისტრირდით → *ქვიზის შექმნა* → შეავსეთ საგანი, კლასი, თემა, მიზანი →
   *კითხვების გენერირება AI-ით* (ან დაამატეთ ხელით) → გადახედეთ → *გამოქვეყნება* → *თამაშის დაწყება*.
   გაიხსნება მასპინძლის ეკრანი 6-ნიშნა კოდით (საუკეთესოა პროექტორზე).
2. **მოსწავლეები** — რამდენიმე ვარიანტი:
   - გახსენით `https://თქვენი-საიტი/join?test=1` **რამდენიმე ჩანართში** — სატესტო რეჟიმში თითოეული ჩანართი ცალკე მოსწავლეა;
   - ან Incognito/Private ფანჯრები, სხვა ბრაუზერები, ტელეფონები.
3. თითოეულში შეიყვანეთ კოდი, სახელი და გვარი. მასპინძლის ეკრანზე მონაწილეები მაშინვე გამოჩნდება.
4. *დაწყება* → კითხვა ჩნდება ყველა მოსწავლესთან. უპასუხეთ — მასპინძელი ხედავს „უპასუხა X / Y“.
   **ყველამ რომ უპასუხოს, კითხვა მაინც აქტიური რჩება ტაიმერის ბოლომდე.**
5. დროის ამოწურვის შემდეგ მოსწავლეები ხედავენ შედეგს, ქულას და ადგილს; მასწავლებელი — განაწილებას და ლიდერებს → *შემდეგი კითხვა*.
6. ბოლოს → *ანალიტიკის ნახვა*: რეკომენდაციები, მიზნები, ქვეთემები, კითხვების ანალიზი, CSV.
7. სცადეთ: გვერდის განახლება თამაშის დროს (პასუხი და ქულა არ იკარგება), პაუზა/გაგრძელება, დაგვიანებით პასუხი.

### Gemini API — უფასო tier
- ხელმისაწვდომია Flash / Flash-Lite ოჯახის მოდელები; Pro მოდელები, წყაროების უმეტესობის მიხედვით, უფასო tier-ში აღარ არის.

- **კონფიდენციალურობა:** უფასო tier-ზე Google-მა შეიძლება გამოიყენოს გაგზავნილი შიგთავსი პროდუქტების გასაუმჯობესებლად. ამიტომ Gemini-ს **არასდროს** ეგზავნება მოსწავლეთა სახელები ან შედეგები — მხოლოდ მასწავლებლის სასწავლო მასალა და პარამეტრები. ნუ ატვირთავთ პერსონალურ მონაცემებს შემცველ მასალას.
- AI საჭიროა **მხოლოდ კითხვების შექმნისას**. კითხვები ინახება ბაზაში და ყოველ თამაშში ხელახლა გამოიყენება — თამაშის დროს AI არ გამოიძახება.
- ანალიტიკა და რეკომენდაციები გამოითვლება **დეტერმინისტულად**, AI-ის გარეშე (ხარჯი 0, ყოველთვის ზუსტი).

## 10. უსაფრთხოება და პერსონალური მონაცემები

- **Row Level Security** ჩართულია ყველა ცხრილზე. მასწავლებელი ხედავს და ცვლის მხოლოდ საკუთარ ქვიზებს, სესიებს, მონაწილეებს და პასუხებს.
- **მოსწავლეებს** (ანონიმური ავტორიზაცია) ცხრილებზე პირდაპირი წვდომა თითქმის არ აქვთ: ისინი იყენებენ მხოლოდ სერვერულ ფუნქციებს (`join_game`, `get_player_state`, `submit_answer`), რომლებიც ამოწმებს მონაწილეობას, თამაშის მდგომარეობას, მიმდინარე კითხვას და დროს **ბაზის საათით**.
- სწორი პასუხი მოსწავლის მოწყობილობაზე იგზავნება **მხოლოდ დროის ამოწურვის შემდეგ**. ქულებს ითვლის ბაზა; ბრაუზერი ქულას ან დროს არ აგზავნის.
- ორჯერ პასუხი შეუძლებელია (უნიკალურობის შეზღუდვა), დაგვიანებული პასუხი უარყოფილია (`TOO_LATE`), შემდეგ კითხვაზე გადასვლა შეუძლებელია ტაიმერის დასრულებამდე (`QUESTION_STILL_ACTIVE`).
- ინახება მხოლოდ მოსწავლის **სახელი და გვარი** და თამაშის პასუხები. ფაილები სერვერზე არ იტვირთება — ტექსტი ბრაუზერში ამოიღება.
- **მონაცემების წაშლა:** *წარსული სესიები* → სესიის წაშლა ან „დასრულებულების წაშლა“ (იშლება მონაწილეები და პასუხებიც). ქვიზის წაშლა შედეგებს არ შლის.
- ძველი ანონიმური მოსწავლე-ანგარიშების გასუფთავება (Supabase SQL Editor, მაგ. თვეში ერთხელ):
  ```sql
  delete from auth.users where is_anonymous and created_at < now() - interval '30 days';
  ```
- უფასო სერვისები არ იძლევა SLA-ს ან სარეზერვო ასლების გარანტიას. მნიშვნელოვანი შედეგები ჩამოტვირთეთ CSV-ით.

## 11. ტესტები და შემოწმებები

```bash
npm run typecheck   # TypeScript
npm run lint        # ESLint
npm test            # Vitest + React Testing Library (ერთეულოვანი და კომპონენტების ტესტები)
npm run test:db     # მიგრაციები + RLS/თამაშის ლოგიკის ტესტები რეალურ PostgreSQL-ზე (საჭიროა PostgreSQL 15+)
npm run build       # production build
```

`test:db` ქმნის დროებით PostgreSQL კლასტერს, უშვებს ყველა მიგრაციას Supabase-ის `auth` სქემის მინიმალურ ემულაციაზე
და ამოწმებს: RLS იზოლაციას მასწავლებლებს შორის, მოსწავლის შეზღუდვებს, ტაიმერს, დაგვიანებულ და განმეორებით პასუხებს,
ქულების ფორმულას, პაუზას, შესვლის rate limit-ს და მონაცემების კასკადურ წაშლას.
